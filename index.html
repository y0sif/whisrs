Voice for the Linux desktop

Press a hotkey, speak, and your words appear at the cursor, in any app on Wayland and X11 desktops. Speech recognition runs in the cloud (Groq, Deepgram, OpenAI, OpenRouter), on your own speech server, or fully offline through whisper.cpp. Other hotkeys read selected text aloud, rewrite it with an LLM, hand a task to a coding agent that answers out loud, or turn a meeting into a timestamped transcript. whisrs is a Rust daemon and a small CLI, open source under MIT.

Quick Install

curl -sSf https://y0sif.github.io/whisrs/install.sh | bash

The script installs the latest release for x86_64 or aarch64, then runs whisrs setup. Run it again to upgrade.

Also available: AUR (whisrs-bin) · Cargo (cargo install whisrs --locked) · Nix · prebuilt tarballs

Features

Dictation

Text is typed while you talk on a streaming backend, or when you stop on a batch one. It uses your keyboard layout's own keys, AltGr and dead keys too. Batch and streaming

Offline, on CPU or GPU

whisper.cpp runs on your machine. A Vulkan, CUDA or HIP build moves it to the GPU. GPU acceleration

Read aloud

Select text and hear it, through Groq, Deepgram, or a local or OpenRouter speech server. [tts]

Voice + LLM

Rewrite the selected text with a spoken instruction, or give named instructions their own hotkeys. It works with any OpenAI-compatible endpoint, local ones included. LLM commands

Voice + coding agents

Give Claude Code, OpenCode, Codex or GitHub Copilot a hotkey. It works in its project and answers in a short reply spoken through [tts], and an optional overlay shows what it is doing. Agent mode

Meeting transcription

Record your mic and the system audio, then get a timestamped Markdown transcript with speaker names and an optional summary. A read-only MCP server lets an agent search your recordings. Recording

Setup and config

A setup wizard, a full-screen config editor that an AI agent can drive too (through taria-mcp, see man whisrs), and profiles that switch the backend and other settings (offline, work) with one command.

Extras

Tray icon, on-screen overlay, word replacements, a vocabulary file, dictation history, and a failed dictation's audio kept for whisrs transcribe-recovery.

Supported Environments

whisrs runs on every Wayland compositor and on X11. Typing, hotkeys, read-aloud, recording and agent mode work on all of them; the desktop decides only window tracking and the overlays.

Desktop Window tracking Overlay
Hyprland, Niri, SwayYesYes
X11, any desktopYesYes
KDE Plasma (Wayland)NoYes
GNOME (Wayland)NoRecording pill through the bundled Shell extension; no agent overlay
Other Wayland compositorsNoWhere the compositor has layer-shell

whisrs types through the Wayland virtual keyboard where the compositor offers it and through uinput everywhere else; on X11, XTEST is an option (Typing). Window tracking returns focus to the window you started in before typing, and tells a terminal from other windows; without it, text goes to the window focused when it is typed. Audio comes from the default input (your PipeWire or PulseAudio default source, through ALSA) or the one [audio] device names.

FAQ

Is there a Wispr Flow or Superwhisper alternative for Linux?

whisrs is an open-source Linux dictation tool and an alternative to Wispr Flow and Superwhisper. Press a hotkey, speak, and the text is typed at your cursor in any app, on Wayland or X11, with cloud or offline speech recognition. See how it compares.

Does whisrs work offline?

whisrs works fully offline with the local-whisper backend, which runs whisper.cpp on your machine: no API key, and no audio leaves it. whisrs setup downloads the model for you. Read-aloud and LLM commands can run on local servers too.

Does whisrs work on Wayland and GNOME?

whisrs works on every Wayland compositor, GNOME and KDE included, and on X11. On GNOME and KDE Wayland sessions everything works except window tracking; GNOME shows the recording pill through the bundled Shell extension and has no agent overlay. See Supported Environments.

Which transcription backend should I pick?

Groq, the default backend, is the easiest start: it has a free tier and needs only an API key. For text typed while you talk, pick deepgram-streaming or openai-realtime; for many hosted models behind one key, OpenRouter; for no cloud at all, local-whisper. See Transcription Backends.

Can I talk to Claude Code by voice?

whisrs gives Claude Code, OpenCode, Codex or GitHub Copilot its own hotkey through an [[agents]] entry. Press it, say what you want, and the agent works in its project; when the turn ends, whisrs speaks a short reply through [tts] and shows it as a notification. See agent mode.

Can whisrs transcribe meetings?

whisrs records your microphone and the system audio with whisrs recording, then writes one timestamped Markdown transcript with speaker names. It records what your computer plays, so it works with any call app, and it can add an LLM summary. See recording.

Which speech recognition backends does whisrs support?

whisrs supports eight backends: groq, deepgram, deepgram-streaming, openai, openai-realtime, openai-compatible-realtime, local-whisper and asr-sidecar. asr-sidecar reaches any OpenAI-compatible transcription server, your own (Parakeet, Nemotron, Moonshine) or hosted, such as OpenRouter. The Transcription Backends table says which of them type while you speak.

How does whisrs type text into applications?

whisrs types keystrokes through a virtual keyboard that follows your layout, so the text lands in any app, terminals included. Typing covers the backends and paste.

Can whisrs read text aloud?

whisrs reads the selected text aloud with whisrs speak (alias read) once [tts] enabled = true, through Groq, Deepgram, or a local or OpenRouter speech server (Read aloud).

Which Linux distributions does whisrs support?

whisrs runs on any Linux distribution with ALSA and libxkbcommon, on x86_64 and aarch64, under systemd or OpenRC. Install it with the install script, a prebuilt tarball, the AUR, cargo install whisrs --locked or the Nix flake (Install). The prebuilt full builds need AVX2 on x86_64 and ARMv8.2 with dotprod on aarch64 (Raspberry Pi 5 and Apple M1, not the Pi 4); on an older CPU, use a -minimal build (the install script picks it) or build from source. Building from source also needs clang and cmake for the bundled whisper.cpp.
